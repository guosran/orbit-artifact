# Implementation-aware direct AIR cost contract

The opt-in `implementation-composite` provider evaluates one prepared complete-program command. It preserves the existing theoretical baseline, v9 `linear-composite` provider, exact `observed-table`, and CGRA models. Adding this interface does not supply calibrated coefficients or claim measured performance.

The four frozen features are `command_count`, `implemented_scalar_f32_product_operations`, `implemented_mixed8_f32_product_operations`, and `hardware_stage_count`. Product counts are logical source scalar operations assigned to the checked scalar or `scalar-product-vector-add-f32:8` implementation. They are not counts of native vector multiply instructions: mixed8 retains scalar products and vectorizes supported additions. Separate add/subtract scalar and vector-pack counts are available as diagnostics. The first model family covers f32 multiply/add/subtract only; division and exponentials remain outside its calibrated domain.

`command_count` sums positive submission counts from checked public execution regions. Device stages and input transfers do not create additional submissions. `execution_region_count` reports the number of these boundaries. The current provider requires exactly one submission; partitioned commands require separate calibration. The boundary is `prepared-command-host-to-host`, with prepared BO policy and observer identity bound through `target.runtime`. Coefficients describe a joint compute, communication, and runtime composite. No DMA-byte, per-edge launch, or separately predicted communication charge is added to the result, and coefficients must not be interpreted as independently measured physical components.

A model uses schema `orbit.direct-air.cost.v1`, kind `implementation-composite`, explicit `calibration`, model identity/version, training-manifest SHA256, target/toolchain/runtime identity, and the prepared-command boundary. `terms` contains exactly the four features above with finite nonnegative millisecond coefficients. Unknown calibration produces no value. A valid calibrated model outside its domain produces `out_of_domain` and a null value. Exact observations continue to use full execution fingerprints and status `measured`; they are not generalized by this provider.

The new `domain` requires `family_fingerprints`, `architecture_fingerprints`, implementation and source-operation whitelists, `allow_tails`, and integer `feature_ranges`. The source family erases static extents and source names while retaining task dependencies, argument/storage bindings, SSA operation structure, all arithmetic constants, affine access maps, loop nesting, lower origins and steps, storage dtype/layout/memory space, and the alias contract. It is a structural membership signature, not an execution key or a proof that every shape is calibrated. Architecture fingerprints bind the checked memory/link/resource description. Exact source fingerprints remain provenance but do not gate this model, allowing predeclared new shapes and tiles in the same family.

Mandatory numeric envelopes cover the four terms, source maximum loop extents on axes 0–2, actual maximum tile spans on axes 0–2, source phase count, DMA bytes, resident payload, local capacity, and cores per stage. Additional native integer facts may further restrict the domain. `allow_tails=false` rejects nonuniform source/tile tails. Static affine unit-step loops and exact supported mixed8 lane coverage are required regardless of the envelope. An envelope does not override backend legality, memory checks, or implementation coverage. The new kind rejects exact-source range fields to avoid confusing a transferable structural domain with v9 source-specific guards.

Training and holdout configurations must be declared before labels are read. Check the native feature matrix rank before fitting the four composite terms: two implementation indicators with a single operation count can be collinear with the command term. Fit only successful, independently audited training observations. Heldout timings remain untouched until parameters and model identity are frozen. Correlated terms and host-wait quantization limit coefficient interpretation; heldout error and ranking uncertainty must be reported without refitting the same holdout.

The CPU cost test uses synthetic coefficients solely to check contracts, family distinctions, numeric-domain rejection, and accounting boundaries. It is not calibration evidence. Real experiment inputs, labels, parameter freezing, and measured results belong in the companion artifact repository.
