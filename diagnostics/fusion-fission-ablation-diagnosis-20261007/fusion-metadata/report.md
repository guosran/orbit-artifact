# R9 fusion metadata failure audit

## Finding

**已证实:** R9 materialization changes both measured fusion kernels. The later imported-seed facts extraction rejects each because the R9 extractor's accepted metadata counts are narrower than the R9 materializer's emitted counts. In these two examples no required fusion attribute is missing: all common fields and the sibling pair names are present and correctly typed; the load-count values are what violate the R9 validator. This is an extraction/seed-facts failure before prediction or scoring, not evidence of a mapper failure or of an illegal IR rewrite.

The exact R9 source is the reconstructed tree `/tmp/orbit-ff-ablation-r9-source-20261007`. `MaterializeNeuraJointRewritePass.cpp:3973`, `:3975`, and `:3977` emits producer-consumer `mode`, `eliminated_stores`, and `eliminated_loads`; retained mode can report one shared load while retaining zero stores. `:4516`, `:4518`, `:4520`, and `:4522` emits sibling mode, zero eliminated stores, a computed eliminated-load count, and both sibling names. In contrast, `ExtractJointTaskGraphFactsPass.cpp:2195` requires sibling eliminated loads to equal zero, and `:2210` requires retained mode to have zero eliminated loads/stores. That validator is called during task-fact extraction at `ExtractJointTaskGraphFactsPass.cpp:2493`; it is also inserted into each structural node at `:2608`.

## Search-stage consequence and scope

In both `fixed-probes-v2/radar-sibling-4-5/search/archive.jsonl:2` and `fixed-probes-v2/radar-pc-16-17/search/archive.jsonl:2`, `neighborhood-seed-1` is invalid with `seed_candidate_facts_unknown:source_owned_pass_failed:incomplete or invalid ... amoeba.neura.fusion metadata`. Each row has `predicted_whole_program_cycles=null`, empty `task_costs` and schedule, and an empty cost-catalogue path. Its action path includes the fusion followed by a `1x2` shape action. The search pass records this failure while preparing the imported seed (`JointNeighborhoodSearchPass.cpp:2592`, `:2599`, `:2602`). **已证实:** this imported seed has no expected numeric score; use **N/A (rejected before prediction/scoring)**, not zero or a poor score. The independent typed materializations separately show that the bad counts are already emitted by fusion materializers; the shape action is not the cause of the validator predicate.

**Evidence-supported but not confirmed for every legal fusion:** R9's source validator is applied to every task carrying fusion metadata, without a resource-shape branch. So sibling outputs with a positive shared-read count and retained producer-consumer outputs with a positive shared-read count are rejected wherever this extraction is attempted. Sibling count zero, retained count zero, and a correctly formed forwarded 1-load/1-store case satisfy the old count predicates. The evidence does not establish that every legal fusion is rejected, nor the count of all such candidates in the deleted funnel logs.

## R11b comparison and cache/native limits

A text comparison of the embedded R11b source contract at `/tmp/orbit-input0-fusion-fission-r11b-20261007/runtime-frozen-r11b/.work/control-variables-and-tiling-20261007/source-model-contract-fusion-fission-funnel-r11b-20261007.json` shows a later extractor change: `ExtractJointTaskGraphFactsPass.cpp:2195` now accepts any nonnegative sibling eliminated-load count and preserves it in the descriptor; `:2217`, `:2218`, `:2219`, and `:2220` allows retained 0–1 loads with zero stores, while forwarded remains exactly 1/1. That directly admits the two observed metadata values, subject to the separate canonical/source checks. This is later-source evidence, not a replay or proof that every candidate passes.

R11b also changes `MaterializeNeuraJointRewritePass.cpp:3917`–`:3931`: it peels only identity `DataMov` wrappers before forwarding, and rejects unsupported/non-identity chains. This is a distinct kernel-wiring safeguard, not the extractor error recorded in the R9 archives. Its branch is relevant to shared-load cases too; therefore an R11b materialization could differ in body wiring from the R9 artifact. No new replay was run.

The R9 cost and score source is graph/task/body scoped. The cost-catalog reader checks source provenance and the expected `source_graph_id` (`AnalyticalTaskCostCatalog.cpp:298`, `:308`) and requires source task IDs to cover the current IR tasks (`:313`). Its per-query key is `(task, mapperRows, mapperCols)` (`:545`); lookup rejects tasks outside current IR (`:606`), and the local prediction cache uses that key while trip count is intentionally reapplied by the caller (`:610`, `:613`). The exact score key includes complete candidate and cost-file contents (`ScoreExactJointTaskCandidatesPass.cpp:1683`, `:1685`), current function IR (`:1695`), task IDs/edges (`:1713`), and the oriented shape descriptor (`:1731`). The profile binding also records task/counter/kernel signatures and `normalized_mapper_body` (`OriginalAmoebaProfileCostAdapter.cpp:1179`, `:1181`, `:1183`). This supports that an old individual-task cost or score cannot silently stand in for the changed fused graph under the R9 binding checks.

The mapper cache is exact-input scoped: it serializes the wrapper with mapper rows/columns (`MapJointSchedulingTasksPass.cpp:624`, `:626`), includes the runtime architecture text (`:637`), and accepts an entry only when the stored complete `input.txt` equals the new key (`:645`). **未知:** R9 records `prediction_run=false`, `native_mapping_run=false`, `ranking_performed=false`, and `cost_catalog_read=false` for both direct fusion materializations; the rejected imported-seed rows likewise contain no score. No specific native mapper outcome, cache hit/miss, fused latency, or performance effect is established.

This audit itself ran no build, mapper, search rerun, source edit, or hash computation. Main-thread forced required-target runs at `fixed-probes-v3/radar-sibling-4-5/diagnostic-search.stderr.log` and `fixed-probes-v3/radar-pc-16-17/diagnostic-search.stderr.log` independently stop on the same metadata predicate before any ordinary neighbor is scored. The report supports only the bounded conclusions above; it does not show that fusion/fission has no effect or that all legal alternatives fail.
