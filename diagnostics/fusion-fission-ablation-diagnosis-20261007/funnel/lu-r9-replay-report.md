The reconstructed exact-R9 extractor requires fusion `mode`, integer `eliminated_loads`, and integer `eliminated_stores`; sibling mode also requires distinct nonempty sibling names and both counts equal zero ([`ExtractJointTaskGraphFactsPass.cpp`](/tmp/orbit-ff-ablation-r9-source-20261007/lib/Backend/Neura/Orchestration/JointScheduling/ExtractJointTaskGraphFactsPass.cpp:2173)). The sibling materializer increments `eliminatedLoads` when it removes a duplicate sibling load, then writes that count into the metadata ([`MaterializeNeuraJointRewritePass.cpp`](/tmp/orbit-ff-ablation-r9-source-20261007/lib/Backend/Neura/Orchestration/JointScheduling/MaterializeNeuraJointRewritePass.cpp:4414), [same file](/tmp/orbit-ff-ablation-r9-source-20261007/lib/Backend/Neura/Orchestration/JointScheduling/MaterializeNeuraJointRewritePass.cpp:4516)). Since these 15 LU sibling candidates were accepted into graph facts, the narrow inference is that they passed the zero-eliminated-load/zero-store sibling gate. The archive does not serialize those attributes or retain their individual MLIR bodies (`candidate_path` is empty), so byte-level body identity and per-candidate attribute dumps remain unavailable. A sibling fusion that deduplicates loads can fail this specific metadata gate; this LU result does not imply that all fusion is accepted or blocked.

The audit only read existing receipts, summaries, archives, checkpoints, and reconstructed source. It did not invoke a compiler, mapper, native executable, or search.
