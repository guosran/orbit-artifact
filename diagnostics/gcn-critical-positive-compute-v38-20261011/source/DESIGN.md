Source38 tests one change to the Source37 compute target selector. A compute group enters the first tier only if the current authenticated typed graph and schedule mark its shape task critical or terminal, the existing complete shape catalogue is known, and at least one current legal pending shape has a supported, finite cached cost with strictly positive duration reduction. Catalogue support and duration use the unchanged remainingShapeComputeOpportunity helper. No predictor query or complete-program scheduler evaluation occurs during selection.

Groups in the first tier precede other compute groups. Inside each tier, the existing critical-weighted gain and family/target lexical ties remain. If the catalogue or typed graph is unknown, every tier bit is false and the original comparison applies. If no first-tier group exists, the original comparison applies. Communication and occupancy comparisons, shape L1/signature order and limit three, all window rules and feedback, pending queues, beam16/diversity4, quota, refresh and original budget256 remain. This does not protect a parent from pruning or guarantee better native cycles.

The new option critical-positive-compute defaults false and is allowed only with the existing fresh directional Joint plus retained communication window. It selects policy schedule-structure-critical-positive-compute-v38. When false, no new output fields are emitted; Source37 decisions and journal object contents remain unchanged. Protocol boolean type and mode mismatches reject. Resume and pause restrictions are unchanged; a Source38 checkpoint cannot be loaded in a different mode. When enabled, every parent_directions event adds all compute groups with their weighted gain and critical-positive tier bit, enabling independent replay of both target selection and ties.
